# Реестр визуальных стилей

Style pack отделяет общий производственный процесс от конкретного визуального языка. Благодаря этому один и тот же конвейер работает с Kinetic Moscow, спокойной продуктовой линией или новым стилем заказчика.

## Как выбрать стиль

1. Открыть `registry.yaml`.
2. Выбрать один style id.
3. Передать только его guide, contact sheet и примеры.
4. Не смешивать два style pack в одном якорном кадре.
5. Записать style id в бриф и manifest.

## Доступные направления

| Style id | Статус | Для чего использовать | Эталон |
|---|---|---|---|
| `kinetic-moscow` | `approved` | эмоциональная реклама, обложки, концепты UrbanAds и РСЯ | `../brand/REFERENCE-CONTACT-SHEET.png` |
| `editorial-explainer` | `draft` | текстовые карусели, объяснение продукта, факты и доверие | `../../РЕЗУЛЬТАТЫ/06_контент/2026-08-01_как-роботакси-видит-город/КОНТАКТНЫЙ-ЛИСТ.png` |

Стиль по умолчанию и единственный утверждённый рекламный стиль —
`kinetic-moscow`. `editorial-explainer` сохранён как воспроизводимый тестовый
style pack, но до отдельного согласования не подменяет стиль по умолчанию.

## Что содержит style pack

- короткое имя;
- статус;
- область применения;
- путь к полному guide;
- основной контактный лист;
- 3–6 принятых примеров;
- prompt preamble;
- неизменяемые признаки;
- антидрейф;
- отдельный чек-лист приёмки.

Для нового направления скопировать структуру из `ШАБЛОН-НОВОГО-СТИЛЯ.md` и
заполнить её. До утверждения якорного кадра запись в `registry.yaml` может иметь
только статус `draft`; после утверждения статус меняется на `approved`.

## Что не является style pack

- один красивый случайный PNG;
- скриншоты Dribbble без описания применяемых приёмов;
- набор конфликтующих референсов;
- интерфейс сайта, автоматически перенесённый в рекламу;
- старая серия без промптов и QA.
