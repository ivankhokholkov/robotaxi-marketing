# Реестр креативов

Один список всех выпущенных креативов. Одна строка — один файл, который ушёл или собирается уйти на площадку.

Зачем он нужен: когда меняется вводная — тариф, цена, механика входа, тэглайн стадии, — надо за минуту понять, **какие макеты сразу стали неправдой**. Без реестра это выясняется по папкам и по памяти, а память между сессиями не переносится. С реестром достаточно сказать системе: «тариф изменился на такой-то, пересобери сет», и она сама найдёт живые строки с этим оффером, пометит их устаревшими и пересоберёт по режиму «повторить».

Реестр и [[ЖУРНАЛ-РАБОТ]] — разные вещи и не дублируют друг друга. Журнал отвечает на вопрос «что вообще было сделано», реестр — «что прямо сейчас живёт на площадках и на каком оффере стоит».

---

## Как этим пользоваться

Три фразы обычными словами, все три работают:

```
покажи реестр креативов
тариф Чилл изменился: теперь первые 10 минут бесплатно, пересобери сет
выведи из работы всё, что стоит на промо-коде 300 ₽
```

Руками строки писать не обязательно — их пишет система после каждого выпущенного макета. Но дописать или поправить руками можно: это обычная таблица в обычном файле.

## Что означает каждое поле

| Поле | Что писать |
|---|---|
| **ID** | код площадки плюс сквозной номер: `SMM`, `РСЯ`, `UA` (UrbanAds), `КАРТЫ`, `НАРУЖКА`, `ЛЕНД`, `ПРЕЗ`. Номер не переиспользуется никогда, даже если макет выведен |
| **Дата** | когда файл собран, не когда запущен |
| **Площадка и формат** | площадка и точный размер: «РСЯ, графический 300×600». Без размера строка бесполезна |
| **Сегмент** | 18–29 или 30–45. Если материал имиджевый и работает на обе — «обе», но это редкий случай, а не значение по умолчанию |
| **Стадия** | знание, интерес, понимание, вовлечение, пробная поездка, репертуар. Стадии — `references/цели.md` |
| **Оффер / тариф** | самое важное поле. Что именно обещает макет: «Чилл, первые 15 минут бесплатно», «промо-код 300 ₽», «нет оффера, имиджевый». По этому полю ищутся макеты при смене вводной, поэтому пишем формулировку, а не «см. текст» |
| **Эталон** | ID замороженного шаблона из [[ЭТАЛОНЫ]], от которого собран макет. Пусто — значит режим «повторить» для него недоступен, придётся согласовывать заново |
| **Файл** | путь от папки `БАННЕРЫ/`. Один файл — одна строка |
| **Статус** | см. ниже |
| **Комментарий** | что важно знать через месяц: дефекты приёмки, «заменяет РСЯ-003», причина вывода |

Токен маркировки `erid` в реестр не выносится: он живёт в `meta.json` рядом с макетом. Причина — токен выдаётся на каждый креатив отдельно и меняется чаще, чем строка реестра.

## Статусы

| Статус | Что значит | Живой? |
|---|---|---|
| `черновик` | собран, заказчику не показан | да |
| `у заказчика` | показан, ждёт решения | да |
| `в работе` | залит на площадку, откручивается | да |
| `выведен` | снят с площадки по решению человека | нет |
| `устарел` | вводная изменилась, макет больше не соответствует правде | нет |
| `брак` | не прошёл приёмку, файл не сдан. Строка остаётся, чтобы не собрать его заново с той же ошибкой | нет |

**Живой креатив** — любой, кроме `выведен` и `устарел`. Именно живые строки ищутся при смене вводной.

Разница между `выведен` и `устарел` не формальная. `Выведен` — макет был верным, но кампания кончилась. `Устарел` — макет стал недостоверным и заливать его нельзя даже случайно. Второе опаснее, поэтому у него отдельный статус, а не комментарий.

Статусы реестра совпадают по смыслу со статусами журнала (`черновик` → `у заказчика` → `утверждён` → `опубликован`), кроме двух последних: у креатива вместо «опубликован» есть жизнь на площадке и есть смерть, и их надо различать.

## Правила ведения

- **Строки не удаляются.** Меняется только статус. Удалённая строка означает, что через месяц никто не вспомнит, почему макет исчез, и его соберут заново с той же ошибкой
- **Одна строка — один файл.** Комплект из пяти размеров — это пять строк, а не одна. Площадки принимают файлы, а не комплекты
- **Оффер пишется словами.** «Тариф Чилл» — недостаточно: при смене цены надо видеть, какая именно цифра стояла на макете
- **Замена фиксируется в обе стороны.** Новый макет получает комментарий «заменяет РСЯ-003», старый — «заменён на РСЯ-011». Иначе через две итерации теряется, что от чего произошло

## Два режима перегенерации

Коротко, полностью — в навыке `banners`.

**«Повторить»** (replicate). Композиция, шрифты, палитра, кадр — те же. Меняется только текст и оффер. Это режим для смены вводной: заказчик уже согласовал, как макет выглядит, и пересогласовывать внешний вид не надо. Опирается на замороженный шаблон из [[ЭТАЛОНЫ]].

**«Разнообразить»** (diversify). Новые варианты в рамках дизайн-системы: другая крупность, другой ракурс, другая московская локация, другой типографический ход. Оффер тот же. Это режим для выгорания креатива и для А/Б, а не для смены вводной.

Правило выбора одно: **изменилась вводная — «повторить», не сработал креатив — «разнообразить»**. Перепутать дорого. «Разнообразить» при смене тарифа означает новый круг согласований там, где его никто не просил.

## Смена вводной: что происходит по команде

Команда обычными словами, например «тариф Чилл изменился на первые 10 минут, пересобери сет». Порядок системы:

1. Найти в реестре живые строки, где в поле «Оффер / тариф» стоит старая вводная. Показать список человеку до любых действий
2. Дождаться подтверждения списка — не додумывать, что попадает под замену
3. Поставить найденным строкам статус `устарел`, дату и причину в комментарии
4. Пересобрать каждый макет в режиме «повторить» от его эталона: новый текст, та же композиция
5. Прогнать тексты через `brand-check` **до** генерации и автопроверку формата после
6. Завести новые строки со ссылками «заменяет ID»
7. Отдать человеку список: что устарело, что пересобрано, что требует нового `erid`
8. Записать строку в [[ЖУРНАЛ-РАБОТ]], раздел «Что менялось в вводных»

Шаг, который нельзя пропускать, — второй. Поле «Оффер» заполняется людьми и по-разному, поиск может зацепить лишнее или пропустить нужное.
