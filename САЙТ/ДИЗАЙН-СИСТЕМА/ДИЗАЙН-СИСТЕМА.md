# Дизайн-система, снятая с копии

Все значения ниже вынуты из настоящих файлов сайта, а не подобраны глазом.
Источник — `assets/.../_next/static/css/*.css` (15 файлов, 281 КБ) и вычисленные
стили живой страницы. Дата снятия — 31.07.2026.

## Устройство размеров: 1rem = 1px при ширине 1440

Это главная механика системы, без неё ничего не сойдётся.

```css
html { font-size: .069vw }                        /* десктоп */
@media (max-width: 767px) { html { font-size: .267vw } }  /* мобильный */
```

`.069vw` при ширине 1440 даёт ровно 1px. Значит **все размеры в макете пишутся
в rem и численно равны пикселям при 1440**: `font-size: 102rem` — это 102 px на
десктопе. При другой ширине окна вся страница пропорционально ужимается или
растягивается, а пропорции не едут.

`.267vw` при ширине 375 тоже даёт ровно 1px, поэтому у мобильной версии свой
набор значений в тех же единицах.

Следствие для работы: **не переводить в px и не смешивать с px.** Пишем в rem,
считаем от 1440 — и всё встанет само.

## Шрифты

- **YSText** — весь текст и заголовки секций. Начертания 300, 400, 500, 700, 800.
- **YSTextCond** — узкое, только для плакатных прописных: заголовок обложки,
  цифры в блоке статистики. Начертания 500, 700 (Heavy).

Файлы лежат в копии: `assets/.../_next/static/media/YSText-*.woff2` и
`YSTextCond-*.woff2`. Подключены локально, интернет не нужен.

Рабочая нагрузка почти вся на 500 — это «средний» вес системы. 400 для текста,
800 для плаката.

## Отступы

Вертикальные между секциями: **100** (крупный), **75** (обычный).
На мобильном: **56** и **42**.

Боковые: **40** (крупный), **35** (обычный), **30** (средний), **10** (мелкий).
На мобильном: **18** и **15**.

Ширина контейнера — **1440**. Минимальная ширина body — **320**.

Реальные отступы секций страницы роботакси (в rem): 150 сверху у блока пользы,
100 у цифр и «как работает», 75 у преимуществ, 50–60 снизу.

## Скругления

Система крупных радиусов — это то, что задаёт узнаваемый вид.

| Токен | Значение | Что скругляет |
|---|---|---|
| `--item-border-radius` | 30 | карточка, плитка — рабочая лошадка |
| `--item-border-radius-sm` | 10 | мелкий элемент, бейдж |
| `--item-border-radius-medium` | 50 | крупная плитка |
| `--item-border-radius-large` | 80 | самая крупная плитка |
| `--layout-border-radius` | 50 | секция-плита |
| `--layout-border-radius-small` | 30 | секция-плита поменьше |
| `--product-border-radius-large` | 80 → 50 на мобильном | продуктовые блоки |
| `--blog-post-border-radius` | 30 → 20 | карточки блога |
| круг | `50%` / `100%` | иконки, номера, точки слайдера |

Кнопка — пилюля: высота **60** (крупная 76, мобильная 50), радиус по высоте.

## Движение

- Плавный скролл всей страницы — библиотека **Lenis**. Это заметно: обычный
  скролл ощущается иначе, и пользователь разницу видит.
- Карусели — библиотека **Splide** (блоки пользы, безопасности, преимуществ).
- Появление блоков и переключение активного пункта — через
  **IntersectionObserver**, а не по клику.
- Кривая ховера: `cubic-bezier(0.22, 0.85, 0.59, 0.97)`.

## Ритм страницы

Светлое и тёмное чередуются, и это несущая конструкция, а не украшение:

```
тёмная обложка #1a1a1a
светлая секция #f4f4f6      плитки
прозрачная (на светлом фоне) карусель
светлая секция              цифры
тёмная секция #1a1a1a       манифест
светлая секция              как работает
прозрачная                  безопасность, преимущества
```

Первый экран всегда тёмный, дальше основной объём светлый, тёмная секция —
смысловая пауза в середине.

## Что взято на веру

Контраст пар по WCAG здесь не пересчитывался: это чужая система, и её проверял
кто-то другой. Перед выпуском своей страницы контраст своих сочетаний считать
заново — особенно если вводится новый акцентный цвет.
