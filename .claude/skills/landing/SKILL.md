# Лендинг

Страница живёт кусками. Каждый блок — отдельный файл, который можно переписать целиком, не трогая остальные семь. `index.html` собирается из блоков по команде, а не правится руками.

## Перед началом

1. Прочитай профиль: `CLAUDE.md в корне папки проекта`. Нет профиля или остались `[PLACEHOLDER]` — останови работу, отправь к навыку `setup`
2. Прочитай `./references/позиционирование.md` и нужный тон — `тон-чилл.md` или `тон-сити.md`
3. Спроси, под какой сегмент страница. «Оба» — допустимый ответ: тогда общая часть идёт нейтральным тоном, а сегментные формулировки живут только в карточках тарифов
4. Проверь, есть ли `ЛЕНДИНГ/tokens.css`. Нет — сначала навык `design-system`, без токенов блок собирать не из чего
5. Спроси, пришли ли тексты от заказчика. Не пришли — работаем на плейсхолдерах, это нормальный режим, см. раздел «Тексты»

Деплой не бывает побочным эффектом другой задачи. Пока человек не сказал «выкладывай» — файлы остаются локальными.

## Раскладка

```
ЛЕНДИНГ/
├── index.html          ← собранная страница. Руками не правится, только пересобирается
├── шаблон.html         ← каркас: doctype, head, подключение tokens.css, место под блоки
├── tokens.css          ← дизайн-система. Правит только навык design-system
├── данные.yaml         ← значения, которые часто меняются. Правит человек руками
├── сборка.py           ← собирает index.html из блоков, подставляя значения
├── build.sh            ← запуск сборки одной командой
└── БЛОКИ/
    ├── 01-обложка.html
    ├── 04-тарифы.html
    ├── 06-вопросы.html
    └── 09-действие.html
```

Каркас страницы живёт в `шаблон.html`, а не в блоке-шапке: блоки содержат только секции. Номера в именах задают порядок сборки, между ними намеренно оставлены промежутки — новый блок вставляется без переименования соседей.

### Что в каждом блоке

| Файл | Блок | Что внутри |
|---|---|---|
| `01-первый-экран` | Первый экран | Одно обещание и одно действие. Что это за сервис, для кого, кнопка. Не абзац текста, а фраза |
| `02-как-это-работает` | Как это работает | Три-четыре шага от заказа до конца поездки. Механика, а не технология |
| `03-безопасность` | Безопасность и барьеры | Прямые ответы на то, чего люди боятся: сбой, отсутствие контроля, безопасность. Барьеры и их веса — в отчёте навыка `audience` |
| `04-тарифы` | Тарифы | Карточки. Один тариф или два — смотри профиль. Здесь и только здесь можно разводить тон по сегментам |
| `05-зона-работы` | Зона работы | Где сервис ездит. Только согласованные зоны из профиля. Не «скоро по всему городу» |
| `06-вопросы` | Частые вопросы | 6–10 вопросов реальными словами пассажира. Первым — самый неудобный |
| `07-действие` | Призыв к действию | Одно целевое действие, то же самое, что на первом экране. Второго варианта нет |

Порядок не случайный: барьеры снимаются до тарифов. Человек, который ещё боится, до цены не доходит.

## Правило блока

Блок обязан оставаться самостоятельным, иначе поблочная правка ломается на второй итерации.

- Один файл — один `<section id="...">`. `id` совпадает с именем файла без номера
- Стили блока живут в `<style>` внутри этого же файла, все селекторы — потомки его `id`. Так правка тарифов физически не может поехать в вопросы
- Значения только из токенов: `var(--color-accent)`, `var(--space-6)`. Захардкоженный цвет или отступ — сигнал, что нужен новый токен, а токены добавляет `design-system`
- Шрифты, сброс стилей и общие правила подключаются один раз в `00-шапка.html`. Блок их не дублирует
- Блок не знает о соседях: не ссылается на их классы, не рассчитывает на их отступы, не продолжает их мысль полусловом

## Цикл правки — главная механика

Именно этот цикл показывается заказчику. Он должен проходить целиком за одну команду.

**Шаг 1. Человек называет блок словами.** «Перепиши тарифы», «первый экран не тот», «добавь вопрос про аварии». Сопоставь с файлом по таблице выше. Не уверен, какой блок имеется в виду, — спроси. Угадывать нельзя: правка не в тот файл выглядит как «система сама что-то переписала».

**Шаг 2. Читай только этот файл.**

```bash
cat "ЛЕНДИНГ/БЛОКИ/04-тарифы.html"
```

`index.html` и соседние блоки не открываются. Они не нужны для работы, а открытый файл рано или поздно оказывается изменённым.

**Шаг 3. Перепиши блок.** Целиком или точечно — по объёму правки. Границы фрагмента не меняются: тот же файл, та же секция, тот же `id`. Текст — через тон сегмента и стоп-слова, факты — только из карточек `knowledge/`.

**Шаг 4. Прогони текст через `brand-check`.** До сборки, а не после. Блок с непроверенным текстом в `index.html` не попадает.

**Шаг 5. Пересобери страницу.**

```bash
cd ЛЕНДИНГ && bash build.sh
```

Сборка не склеивает файлы: она подставляет значения из `данные.yaml` в места вида `{{тарифы.чилл.бесплатных_минут}}` и оборачивает результат в `шаблон.html`. Простое `cat БЛОКИ/*.html > index.html` даст страницу без подстановок и без `<head>` — так не собираем.

Порядок задаётся номерами в именах файлов. Хочешь переставить блоки местами — переименуй файл, а не правь `index.html`.

Отчёт сборки сам говорит, что не так: какие подстановки не нашли значения и какие неподтверждённые метки попали на страницу. Метки на странице — не баг, а сигнал: публиковать с ними нельзя.

**Шаг 6. Проверь, что задет ровно один блок.**

```bash
ls -la index.html && wc -c index.html   # рабочая папка не под git
```

Ожидаемый результат — два файла: сам блок и `index.html`. Появился третий — что-то пошло не так, остановись и разберись, прежде чем показывать результат.

**Шаг 7. Деплой — если и только если человек сказал.**

Полная пересборка страницы делается один раз, при первой сборке. Дальше — только этот цикл. Просьба «поправь заголовок» не превращается в перегенерацию восьми файлов.

## Быстрая правка значений — без навыка и без автора

Это оказалось главным, что заказчик имел в виду под «инструментами перегенерации». Дословно:

> «я имел ввиду инструменты перегенерации, чтобы мне было понятно и легко можно было менять блоки — ну скорее всего **не менять местами, а менять контент оперативно**. Если условно тариф 15 минут первые бесплатно, а они 10 становятся, или как-то по-другому денежная мотивация становится — чтобы я мог зайти быстренько это всё поменять, **без того чтобы тебя выдёргивать**»

То есть частый сценарий — не «перепиши блок», а «поменяй цифру». И сделать это он хочет сам, руками, без запуска навыка.

### Механика

Значения, которые меняются часто, живут **в одном файле**, а блоки их подставляют:

```
ЛЕНДИНГ/данные.yaml     ← правится руками
ЛЕНДИНГ/БЛОКИ/*.html    ← содержат подстановки, не значения
```

```yaml
# ЛЕНДИНГ/данные.yaml
сервис:
  название: "[ПОДТВЕРДИТЬ: название рабочее]"
  города_сервиса: "[ПОДТВЕРДИТЬ: в документе Москва и Санкт-Петербург]"
  город_кампании: "Москва"
тарифы:
  заголовок: "Два тарифа"
  модель: "[ПОДТВЕРДИТЬ: один тариф или два]"
  чилл:
    бесплатных_минут: 15
    подача_минут: "10 минут [ПОДТВЕРДИТЬ У ЗАКАЗЧИКА]"
  сити:
    подача_минут: "5 минут [ПОДТВЕРДИТЬ У ЗАКАЗЧИКА]"
```

Заголовок блока тарифов тоже значение, а не текст в блоке: сколько тарифов будет — открытая развилка заказчика. Города сервиса и город кампании разведены: пилот заявлен шире, реклама идёт под Москву.

В блоке — подстановка, а не число:

```html
<p>Первые {{тарифы.чилл.бесплатных_минут}} минут бесплатно</p>
```

Правка цифры: открыть `данные.yaml`, поменять одно значение, запустить `build.sh`. Обновится везде, где значение встречается.

### Что чем правится

| Что изменилось | Чем правим | Кто делает |
|---|---|---|
| Цифра, название, город, срок | `данные.yaml` + пересборка | Заказчик сам |
| Смысл или тон блока | Перегенерация блока навыком | Зовёт систему |
| Структура страницы, порядок блоков | Навык, с обсуждением | Зовёт систему |

Разница принципиальная: **перегенерация нужна, когда меняется смысл; правка данных — когда меняется значение.** Путать их дорого. Перегенерировать блок ради замены «15» на «10» — значит получить новый текст там, где заказчик уже одобрил старый.

Иван предлагал на встрече CMS или MDX как варианты. Они годятся, если страница вырастет. По умолчанию файл данных проще: не требует сборщика, читается глазами, правится в любом редакторе.

## Слоты под моушен

Анимация для заказчика — главный аргумент страницы:

> «он точно должен быть с анимацией, потому что **анимация это основное selling point**. Нужно будет показать представление окружения автомобиля: ты едешь, видишь движение вперёд, видишь физический мир, а на сплит-экране мы должны показать, как машина это видит через лидар — она видит это как точки координации в пространстве. И чтобы человек понимал, что под капотом ИИ, который видит на 250 метров, 360 градусов»

Но делать моушен — не наша задача:

> «это не к тебе сейчас вопрос, что ты должен это делать. Это мне по-хорошему всё должны сдать, нам нужно просто **прикрутить на сайт**»

И рамка, которую заказчик поставил жёстко:

> «сайт, лендинг — чтобы он нам помогал, но **не был как бы проект в проекте**, чтобы я на нём не завяз, потому что мне здесь нужна скорость движения»

### Как готовим слот

Блок собирается с явным местом под материал: контейнер нужного соотношения, подпись, что сюда встаёт, и заглушка, которую невозможно спутать с готовым.

```html
<div class="слот-моушен" data-соотношение="16:9">
  <p>[СЛОТ ПОД МОУШЕН: вид от первого лица в движении.
     Ожидается от дизайнеров. Формат уточнить.]</p>
</div>
```

Ожидаемые слоты:

| Слот | Что встаёт |
|---|---|
| Вид от первого лица | Движение вперёд, физический мир как его видит пассажир |
| Представление лидара | Облако точек, то же окружение как его видит машина |
| Сплит-экран | Два предыдущих рядом — «как видит человек / как видит машина» |

### Запрет

**Навык не генерирует моушен и не рисует его CSS-анимацией «пока нет исходников».**

Самодельная анимация вместо профессиональной обесценит именно тот аргумент, на котором держится страница, а переделывать поверх самоделки дороже, чем собрать с нуля. Плюс это ровно тот случай, когда «проект в проекте» и начинается.

Пока исходников нет — страница собирается и показывается с заглушками. Это не повод её не собирать: структура, тексты и цикл правки проверяются без моушена.

## Тексты

Тексты собирает заказчик — это зафиксировано на входе. Пока их нет, блок собирается на плейсхолдерах.

Формат плейсхолдера — прямо в разметке, видимый на странице:

```html
<h1><span class="placeholder-text">[ТЕКСТ ОТ ЗАКАЗЧИКА: заголовок первого экрана, 4–7 слов]</span></h1>
```

Стиль `.placeholder-text` живёт в `00-шапка.html`, а не в токенах, и выглядит намеренно чужеродно: жёлтая подложка, пунктирная рамка, моноширинный шрифт. Плейсхолдер, который можно принять за готовый текст, — это не плейсхолдер, а тихая ложь. Умрёт стиль вместе с последним плейсхолдером.

Три разных пометки, не путать:

| Метка | Когда |
|---|---|
| `[ТЕКСТ ОТ ЗАКАЗЧИКА: что нужно]` | Текста нет, его пишет клиент |
| `[ПРОВЕРИТЬ: что именно]` | Цифра или факт без карточки в `knowledge/` |
| `[ПОДТВЕРДИТЬ: категория ВАТС]` | Всё, что упирается в правовой режим |

После каждой сборки посчитай, сколько плейсхолдеров осталось, и назови число в ответе:

```bash
grep -o 'ТЕКСТ ОТ ЗАКАЗЧИКА\|ПРОВЕРИТЬ:\|ПОДТВЕРДИТЬ:' ЛЕНДИНГ/index.html | sort | uniq -c
```

Отдельно про карточки тарифов. В документе заказчика они написаны через формулировку «без водителя». Дословно её не переносим: пока в профиле не подтверждена категория ВАТС, на её месте стоит `[ПОДТВЕРДИТЬ: категория ВАТС]`. Это не придирка — недостоверное утверждение в рекламе бьёт по рекламодателю, то есть по клиенту.

## Деплой на превью

Превью — рабочая ссылка для заказчика, а не публикация. Из этого следует всё остальное.

**Обязательно, без вариантов:**

- **Пароль.** Ставится средствами хостинга (в Vercel — Deployment Protection → Password), не в разметке. Ссылка без пароля не отдаётся никому, включая заказчика
- **Запрет индексации.** В `00-шапка.html` — `<meta name="robots" content="noindex, nofollow">`, рядом с `index.html` — `robots.txt` с `Disallow: /`. Два механизма, потому что первый не спасает от прямых ссылок, а второй от кэша
- **Никаких закрытых данных.** Реальные тарифы, целевые метрики, число машин и всё, что в профиле перечислено в разделе «Границы NDA», на превью не едет. На их месте плейсхолдеры — до отдельного письменного разрешения

Перед тем как выкладывать, пройди пять пунктов:

1. `index.html` пересобран после последней правки блока
2. Плейсхолдеры сосчитаны, число названо в ответе
3. Закрытых данных из профиля на странице нет — проверено поиском по конкретным полям
4. `noindex` на месте, `robots.txt` рядом, пароль включён
5. Человек сказал «деплой» в этой сессии

Команда:

```bash
npx vercel deploy ЛЕНДИНГ
```

В ответе отдай три вещи: ссылку, пароль и строку «это превью под паролем, не публикация». Без последней строки ссылка через день окажется в чужой презентации.

## Чего не делать

- Не пересобирать всю страницу ради правки одного блока. Это ровно то, что клиент покупает: правка блока стоит одну команду
- Не править `index.html` руками. Он собранный, следующая сборка затрёт правку молча
- Не деплоить без явной команды. Ни «заодно», ни «чтобы показать», ни «я всё равно уже собрал»
- Не подставлять текст за заказчика. Пустой плейсхолдер — его блокер, придуманный текст — уже наш
- Не писать «без водителя», пока категория ВАТС не подтверждена в профиле
- Не противопоставлять такси с водителем — правило заказчика, на лендинге ломается чаще всего в блоке безопасности
- Не заводить в блоке второе целевое действие. Две кнопки в первом экране — это минус конверсия, а не выбор

## Блок происхождения — обязателен

Материал заканчивается строкой, которая связывает его с базой:

```
---
**Опирается на:** [[хаб]], [[файл-ядра]], [[карточка-факта]]
```

Хаб — картина, из которой вырос вывод. Ядро — правила, которые применялись. Карточки — цифры, которые использованы.

Без этого блока материал не считается готовым: он выпадает из графа знаний, и через месяц никто не восстановит, на чём он стоял. Проверяется командой `python3 .claude/scripts/wiki.py arch`.
