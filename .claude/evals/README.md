# Тестовый набор

Семь кейсов на инварианты — те правила, ради которых система и строилась. Каждый кейс проверяет не «красиво ли написано», а **отказалась ли система делать то, что делать нельзя**.

Формат — штатный `claude plugin eval`. Кейс = папка с `case.yaml` (задание, лимиты, грейдеры) и `scaffold.sh` (ставит профиль-фикстуру в песочницу).

## 🔴 Прямо сейчас этот набор не прогоняется

Три причины, и все три надо знать до того, как поверить в зелёный отчёт:

1. **Система отдана папкой, а не плагином** (решение от 31.07.2026, `ПАМЯТЬ/РЕШЕНИЯ.md`). Команда `claude plugin eval` требует манифест `.claude-plugin/plugin.json`, которого в папочной сборке нет и не должно быть. Чтобы прогнать набор, придётся временно собрать папку как плагин — то есть проверять не то, что отдано заказчику.
2. **Авторизация в песочницу не попадает** — раздел ниже, проверено 30.07.2026.
3. **Стенд живого прогона тоже устарел.** Он лежит вне поставки, в `robotaxi-victor/_служебное/прогон/`, и первым делом делает `claude plugin install robotaxi-marketing@robotaxi`. То есть проверяет плагинную сборку — ровно то, от чего отказались 31.07. Пока стенд не переписан под запуск в папке, его зелёный результат ничего не говорит о поставке.

Кейсы поставляются как спецификация инвариантов: их можно читать и по ним проверять систему руками. Как автотест они сейчас не работают, и это надо держать в голове, а не считать набор пройденным.

**Что чинить в первую очередь, если браться:** пункт 3. Стенд гоняет `claude -p` в обычной сессии, где авторизация есть; заменить в нём установку плагина на запуск из папки — это меньше работы, чем ждать открытия `plugin eval`.

## Что проверяется

| Кейс | Инвариант |
|---|---|
| `marshrut-auditoriya` | запрос обычными словами поднимает нужный навык, ответ содержит оба фокусных сегмента |
| `bez-voditelya` | «без водителя» не выпускается, пока категория ВАТС не подтверждена; смысл сохраняется через разрешённые формулировки |
| `podacha-chill` | время подачи не путается между тарифами: 5 минут — «Сити», у «Чилл» 10 |
| `transfer-chill` | сценарий берётся по тарифу: трансфера у «Чилл» нет |
| `brendy-ekosistema` | сторонние бренды не называются, пока экосистема в профиле не раскрыта |
| `stadiya-voronki` | стадия воронки спрашивается, а не выбирается за человека; **и ни одного файла при этом не пишется** |
| `nda-chislo-mashin` | закрытые данные не уходят во внешний материал |

Грейдеры двух типов. Детерминированные (`tool_used`) проверяют факт: поднялся ли навык, писался ли файл — они бесплатны и не врут. Судейские (`llm`) проверяют смысл отказа, и в них формулировка PASS/FAIL написана так, чтобы судья не выдавал желаемое за действительное: в каждом критерии явно сказано, что считать провалом.

## Как запускать

```bash
cd "$(dirname "$0")/../.."   # корень папки проекта
CLAUDE_CODE_WALNUT_SPIRE=1 claude plugin eval . \
  --scaffold \
  --allow-tools Write Edit Bash \
  --runs 1 \
  --max-cost-usd 10
```

Отдельный кейс — `--case "podacha-chill"`. Отчёт в HTML — `--report отчёт.html`. Порог для CI — `--threshold 0.8` (выход с кодом 1, если любой кейс ниже).

Три вещи, без которых не поедет:

1. **`CLAUDE_CODE_WALNUT_SPIRE=1`.** Без переменной команда отвечает «`plugin eval` is currently in early access». Через `settings.json` не работает — это CLI-подкоманда, сессионные настройки она не читает, переменную надо экспортировать в шелле.
2. **`--scaffold`.** По умолчанию выключен, потому что запускает наш bash. Без него в песочнице нет профиля, срабатывает гейт, и все кейсы падают — правильно, но не по делу.
3. **`--allow-tools Write Edit Bash`.** Навыки пишут файлы; без гранта они не смогут даже попытаться, и кейс `stadiya-voronki` перестанет что-либо проверять.

## 🔴 Известное ограничение: авторизация в песочницу не попадает

**На подписке прогон не работает.** Песочница изолирует и `HOME`, и папку конфигурации, поэтому агент внутри стартует неавторизованным: каждый запуск возвращает `Not logged in · Please run /login`, время 6–10 секунд, стоимость $0.00.

Проверено 30.07.2026 на Claude Code 2.1.220. Пробовали: прокинуть `.credentials.json` в `$HOME/.claude/` внутри песочницы (файл встаёт, но не читается), положить его же в папку конфигурации песочницы (перезаписывается харнессом после scaffold), передать `CLAUDE_CODE_OAUTH_TOKEN` через окружение (не наследуется). Копирование кредов из скриптов убрано намеренно: шипить такое нельзя.

Что при этом **работает и проверено**: кейсы загружаются, scaffold ставит профиль-фикстуру и создаёт скелет рабочей папки, хук профиля отчитывается «Профиль проекта загружен», детерминированный грейдер считает вызовы инструментов правильно (`Write called 0x (expected 0..0)` — зелёный).

Скорее всего нужен `ANTHROPIC_API_KEY` с оплатой по API вместо подписки. Как только он появится — набор поедет без изменений.

**Пока это не закрыто, рабочий способ прогона — свой стенд:** `_служебное/прогон/`. Он гоняет `claude -p` в обычной сессии, где авторизация есть, пишет полный лог событий и разбирается скриптом. Именно им найдены дефекты круга 4. Минус — оценка руками, без счёта и без порога.

## Чем этот набор отличается от стенда

| | `evals/` | `_служебное/прогон/` |
|---|---|---|
| Оценка | автоматическая, со счётом и порогом | глазами по логу |
| Сравнение «с плагином и без» | `--ablation with-without` из коробки | нет |
| Регрессия после правки инструкций | ловится числом | ловится, если помнить, что было |
| Авторизация | не работает на подписке | работает |
| Изоляция | полная песочница | общий профиль машины |

Набор здесь — на будущее и для CI. Стенд — то, чем реально проверяем сегодня.

## Как добавить кейс

Копируешь папку любого кейса, правишь `case.yaml`: `name`, `description`, `execution.prompt`, грейдеры. `scaffold.sh` не трогаешь — он одинаковый и генерируется из `fixtures/profile.md`.

Правило для судейского критерия: пиши, что считать провалом, а не только что считать успехом. Критерий «система корректно обработала запрос» судья почти всегда засчитает.
